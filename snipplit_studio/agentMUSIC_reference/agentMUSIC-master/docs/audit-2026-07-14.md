## 0. Проект, зона ответственности, итог дня

**Проект:** AgentMUSIC — сервис генерации караоке-видео (трек → транскрипция → припев → рендер с футажами). Интегрируется с AF-платформой (ферма телефонов) как внешний провайдер `agenmusic`: Go-адаптер в AF-video-generator ходит в HTTP API AgentMUSIC (`POST /api/v1/videos` → поллинг `GET /api/jobs/{id}` → скачивание mp4). Затронуты 3 репозитория: **agentMUSIC**, **AF-video-generator**, **AF-frontend**.

**Сделано за день (14.07.2026):**
1. Закрыт блокер №1: сервер (Coolify, 10.25.21.190:18009 / music.atom-farm.com) передеплоен на master — эндпоинт `/api/v1/videos` реально доступен.
2. Скачивание трека по **названию или ссылке** без Spotify API (обход Spotify-403): новый `modules/track_resolver.py` — публичный Deezer search + og:title scrape → Deezer(ARL)/yt-dlp. Коммиты `f044d7f` (фича) + `9c908db` (SSRF-hardening по итогам ревью). Ветка запушена, **не смержена**.
3. Контент-пул ~500 клипов (AF-video-generator `feat/music-pool`): scheduler af-content наполняет команды промптами из curated-источника; смержено в main (`8aff6d2`), запушено.
4. Pool-UI в AF-frontend (грид пула + claim→publish): ветка `feat/agenmusic-pool-ui`, открыт PR #4 (включая фиксы коллеги `8098576`).
5. Разведка по прогреву библиотеки треков на сервере: MinIO настроен, но бакет `music-tracks` **пуст**; у OWNER_ID 694509855 всего ~2 пригодных трека.
6. Документация: embedding UI (`07d5814`), спека платформы (`1d846c0`).
7. **Незакоммичено:** инструментарий массовой генерации — `scripts/fetch_chart_tracks.py`, `scripts/fetch_footage_pool.py`, `scripts/generate_batch.py` + `batch_queries` в config.yaml + правки `footage_searcher.py` (page_spread, удаление битых недокачек).

**Какой информации не хватает (блокирует следующий шаг):**
- Есть ли на сервере `yt-dlp` и валидный `DEEZER_ARL` (+`rip`) — без этого freeform-скачивание после мержа не заработает. Проверка: `scripts/check_readiness.py` (секция downloaders) на сервере.
- Точный формат `object_key` у content-distributor (bucket+'/'+original_key — предположение, нужно подтвердить на ферме).
- Значение `AGENTMUSIC_OWNER_ID` на сервере (25 треков лежат под id 234658540 и невидимы интеграции).
- Доступ к ферме для реального E2E — dev-машина не достаёт до 10.25.21.190.

## 2. НЕ ПРОВЕРЕНО (СРОЧНО)

1. **Батч-инструментарий (`fetch_chart_tracks.py`, `fetch_footage_pool.py`, `generate_batch.py`) — ни одного запуска.**
   Доказательство отсутствия проверки: нет `output/batch/tracks_manifest.json`, футаж-кеш пуст. Опасно: скрипты импортируют приватные функции (`_download_item`, `_http_get`, `_deserialize_lyrics`) — хрупкая связка, сломается молча при любом рефакторинге модулей; resume-логика манифестов не проверялась вообще.
   **Завтра:** смоук по инструкциям из docstring'ов: `--dry-run` → `--target 2` → `--per-query 2 --rounds 1` → `generate_batch --limit 2 --videos-per-track 2`. Только после смоука — коммит.

2. **Правки `modules/footage_searcher.py` не закоммичены и не покрыты тестами.**
   Опасно: это общий модуль — им пользуется и бот/prewarm, не только новый скрипт. Ошибка в `_remove_partial` или в пробросе `page_spread` уронит прогрев футажей в проде.
   **Завтра:** прогнать `uv run pytest tests/ -v` + `uv run ruff check .` по текущему рабочему дереву, добавить тест на удаление недокачанного файла.

3. **Freeform-скачивание на сервере: зависимости не подтверждены.**
   Код помечен «готов, запушен», но мерж сознательно отложен, потому что наличие `yt-dlp`/`DEEZER_ARL` на проде никто не проверял. Опасно: после мержа и редеплоя фича будет отдавать ошибки пользователям UI.
   **Завтра:** запустить `scripts/check_readiness.py` на сервере (LAN/docker exec), после зелёной секции downloaders — мерж `9c908db` → master → редеплой → смоук `POST /api/v1/videos` со ссылкой.

4. **Pool: publish-цепочка claim→download→push→markPublished не гонялась вживую.**
   tsc и go-тесты не доказывают, что distributor примет `object_key` в формате `bucket+'/'+original_key`.
   **Завтра (на ферме):** один ручной прогон publish из pool-грида, зафиксировать формат ключа.

5. **Прогрев библиотеки треков не сделан.**
   Бакет `music-tracks` пуст, у интеграционного OWNER_ID ~2 пригодных трека. Опасно: демо/E2E у коллег упадёт на любом «не том» промпте (Spotify-403).
   **Завтра:** залить mp3 `Artist/Title.mp3` в бакет и прогнать import-batch по LAN (не через Cloudflare — таймаут ~100 с), либо выставить `AGENTMUSIC_OWNER_ID=234658540` (там 25 треков).

## 4. АУДИТ ПРОВЕРКИ (как проверяли)

План верификации **был и применялся к коду в репозиториях** — pytest 79 green + ruff (agentMUSIC), `go build/vet/test` green +5 тестов (AF-video-generator), tsc (AF-frontend), Playwright со стаб-оркестратором для UI-эмбеда, живые HTTP-проверки прод-сервера для блокера №1 и состояния MinIO; **но** реального сквозного E2E на ферме не было ни для одной цепочки (dev-машина физически не достаёт до 10.25.21.190), а весь незакоммиченный батч-инструментарий (3 скрипта + правки footage_searcher) не имеет **ни одного** запуска и ни одного теста — по правилам аудита это «НЕ ПРОВЕРЕНО», несмотря на аккуратные docstring'и.

**Вердикт одной строкой:** серверный контракт и код в репах подтверждены тестами и живыми запросами; всё, что за пределами unit-уровня (ферма, downloaders, publish, батч-скрипты), держится на «должно работать» — завтра начинать с пунктов раздела 2.
